## 🎯 Pedagogical Blueprint & Objective
Guide students through the 3-section structure of `.l` specification files, regular expression action bindings, and runtime variables of the Flex/Lex scanner generator (Michael E. Lesk & Eric Schmidt 1975; Vern Paxson 1990; John Levine *flex & bison* Chapter 1 & 2): master the **3-Section Flex Architecture (`%{ Declarations %} %% Rules & Actions %% C User Routines`)**, formulate the role of the **`yylex()` Main Scanner Routine**, evaluate the **Global Lexer Communication Variables** (**`yytext`** pointing to the null-terminated matched lexeme, **`yyleng`** storing lexeme length, **`yylval`** semantic value union shared with Bison/Yacc, and **`yyin` / `yyout`** file streams), handle whitespace filtering, line counting (`yylineno`), and lexical error recovery.

## 🤖 LLM Prompt Generation Rules & Directives

1. **Slide 1 (`theory`):** State Flex Specifications & `yylex()` Architecture (Paxson 1990; Levine Chapter 1):
   - **The 3-Section `.l` File Structure:**
     ```flex
     %{
       #include "y.tab.h" /* Header with token constants generated by Bison */
       #include <string.h>
     %}
     /* Definitions & Named Regexes */
     DIGIT   [0-9]
     ID      [a-zA-Z_][a-zA-Z0-9_]*
     %%
     /* Rules & C Actions */
     "if"            { return IF; }
     "while"         { return WHILE; }
     {ID}            { yylval.str = strdup(yytext); return ID; }
     {DIGIT}+        { yylval.num = atoi(yytext); return NUM; }
     [ \t\r\n]+      { /* Ignore whitespace */ }
     .               { printf("Lexical Error: %s\n", yytext); }
     %%
     /* User C Code */
     int yywrap() { return 1; }
     ```
   - **The Core Global Variables:**
     - `int yylex()`: Main scanner entry point returning integer token code.
     - `char *yytext`: Null-terminated string containing the matched lexeme.
     - `int yyleng`: Length of matched lexeme in characters.
     - `YYSTYPE yylval`: Semantic attribute value union passed to the parser!
2. **Slide 2 (`ordering`):** Provide 5 steps of building and running a Flex scanner: (1) write lexical patterns and C action blocks in a specification file named scanner.l, (2) run the command 'flex scanner.l' to generate the C source file lex.yy.c, (3) compile lex.yy.c with gcc/clang along with the main program or parser, (4) run the compiled binary which opens input file stream yyin, (5) the parser invokes yylex() repeatedly in a loop, receiving integer token codes and yylval values until yylex() returns 0 (EOF)!
3. **Slide 3 (`matching`):** Pair 4 Flex variables/functions (yylex(), yytext, yylval, yywrap()) with their roles.
4. **Slide 4 (`fill_in_blank`):** Single sentence blank testing recall that yytext stores the pointer to the matched lexeme. Plain text only.
5. **Slide 5 (`quiz`):** Quiz on how Flex (`yylex()`) communicates with Bison/Yacc (`yyparse()`): In a compiler combining a Flex lexer and a Bison parser, what exact dual information is transmitted each time `yyparse()` calls `yylex()`? (`yylex()` directly returns an **integer token ID as its function return value** (e.g. `NUM`, `ID`, `IF`) to direct the parser's grammatical state transitions, while simultaneously populating the **global union variable `yylval` with the semantic attribute value** (e.g. the integer value `42` or a string pointer to `"variable_name"`)).
