## 🤖 LLM Prompt Generation Rules & Directives

1. **Slide 1 (`theory`):** State Ed25519 & EdDSA (Bernstein et al. 2012; RFC 8032):
   - **Twisted Edwards Curve Equation:**
     $$\mathbf{-x^2 + y^2 = 1 - \frac{121665}{121666} x^2 y^2 \pmod{2^{255}-19}}$$
     - Complete addition formulas: No special cases for $P = Q$ or $P = -Q$; constant time!
   - **Deterministic Nonce Synthesis:**
     $$\mathbf{r = \text{SHA-512}(K_{\text{right}} \ || \ M) \pmod \ell}$$
     - Generated by hashing private key prefix with message $M$.
     - **Deterministic Invariant:** Signing the same message twice produces the exact same signature. Nonce reuse is physically impossible!
   - **The Signature Pair $(R, S)$ (64 Bytes Total):**
     $$\mathbf{R = r \cdot B \qquad ; \qquad \mathbf{S = \big(r + \text{SHA-512}(R \ || \ A \ || \ M) \cdot s\big) \pmod \ell}}$$
     - $R$ is compressed 32-byte point, $S$ is 32-byte scalar.
2. **Slide 2 (`ordering`):** Provide 5 steps of the Ed25519 signing procedure: (1) hash 32-byte private seed with SHA-512 to produce 64-byte digest (split into secret scalar s and key prefix K_right), (2) compute deterministic ephemeral nonce scalar r = SHA-512(K_right || M) mod L, (3) compute curve point R = r * B and encode R into 32 compressed bytes, (4) compute challenge hash k = SHA-512(R || A || M) mod L where A is public key, (5) compute scalar S = (r + k * s) mod L and output compact 64-byte signature (R || S)!
3. **Slide 3 (`matching`):** Pair 4 Ed25519 constructs (Complete Addition Law, Deterministic Nonce r, Signature Pair R || S, Scalar s Clamping) with their functions.
4. **Slide 4 (`fill_in_blank`):** Single sentence blank testing recall that Ed25519 uses SHA-512. Plain text only.
5. **Slide 5 (`quiz`):** Quiz on why Ed25519 prevents nonce reuse: Why is Daniel J. Bernstein's Ed25519 signature scheme mathematically immune to the catastrophic nonce-reuse private key extractions that destroyed Sony's PS3 and other ECDSA systems? (In Ed25519, the ephemeral scalar nonce $r$ is **NOT generated using a hardware random number generator (TRNG)**; instead, it is **derived deterministically via $r = \text{SHA-512}(K_{\text{right}} \ || \ M) \pmod \ell$**; for a given message $M$, the nonce $r$ is uniquely locked to that specific message content; it is mathematically impossible for two different messages to ever share the same nonce $r$ unless a SHA-512 collision is discovered).
